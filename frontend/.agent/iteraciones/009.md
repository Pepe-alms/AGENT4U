# Iteración 009 — T06 Render de respuestas | HECHA

Fecha: 2026-10-03. Rama: `featue/merge`, **sin commits**.

## Dependencias nuevas: `marked` + `dompurify`

Dos paquetes y **cero dependencias transitivas** (el árbol pasa de 72 a 74).

- `marked`: parser de markdown, 520 KB en disco, sin dependencias.
- `dompurify`: el sanitizador estándar de HTML en el navegador.

**Alternativa descartada: `react-markdown`.** Arrastra el ecosistema
unified/remark/rehype (más de diez paquetes) y, para este caso, es peor: en
streaming reconstruye todo el árbol de React en cada trozo que llega, mientras
que con `marked` + `innerHTML` memoizado el coste es un parseo y una asignación.

**Coste:** el bundle pasa de 213 KB a 289 KB (67 → 92 KB gzip). Es mucho para
una funcionalidad que solo usa el chat, así que queda anotado para T16: el
módulo se puede cargar de forma diferida.

## Constructor

1. **`shared/lib/markdown.ts`**. Parsea y **después** sanea; lo que sale es lo
   único que puede entrar en `dangerouslySetInnerHTML`. El texto viene de un
   LLM que ha leído documentos que alguien subió: tratarlo como HTML de
   confianza sería una vía de XSS directa.
   - Lista blanca estricta de etiquetas y atributos.
   - `ALLOWED_URI_REGEXP` limitado a `http(s)`, `mailto`, anclas y rutas.
   - **`img` fuera a propósito**: una imagen remota en la respuesta es una
     petición a un tercero desde la página del usuario, y en un RAG sobre
     documentos propios no aporta nada.
   - Retoques posteriores sobre HTML ya saneado: `target="_blank"` con
     `rel="noopener noreferrer"`, y un botón de copiar por bloque de código.
     El botón se añade **después** de sanear para que sea marcado nuestro y no
     algo que el modelo pueda falsificar dentro de su respuesta.
2. **`shared/ui/BotonCopiar.tsx`**: con confirmación en `aria-live`, porque si
   no el cambio de texto del botón pasa desapercibido para un lector de
   pantalla. Si el portapapeles falla (sin contexto seguro) no se monta un
   error: el texto sigue siendo seleccionable.
3. **`features/chat/Respuesta.tsx`**: memoiza el parseo por texto, que es lo
   que cambia en cada trozo. Los botones inyectados no pueden tener `onClick`
   de React, así que se resuelven con **delegación** desde el contenedor.
4. **Estilos de prosa** con selectores de elemento, porque el HTML lo genera
   `marked` y no se le pueden poner clases. Tablas y bloques de código con
   `overflow-x: auto` para que no rompan el layout.
5. **Copiar la respuesta entera**, solo cuando ha terminado: a mitad del stream
   copiaría media frase.

### Criterio de HECHO: listas, código y tablas

Sobre una respuesta real llegada por SSE: `h2=1, ul=1, li=3, table=1 (th=3,

### Devolución 1 (resuelta a medias, y la otra mitad era mía)

A 375 px el botón de copiar código resultó:

- **Inalcanzable con el dedo**: solo aparecía en `:hover`, y en táctil no hay
  hover. **Fallo real**, corregido con `@media (hover: none)`.
- *Aparentemente* invisible al recibir el foco. Falso: se estaba leyendo
  `getComputedStyle` **durante la transición de 140 ms**. A los 400 ms la
  opacidad es 1 y vuelve a 0 al perder el foco. Aun así se cambió
  `:focus-visible` por `:focus`, porque la visibilidad de un control que tiene
  el foco no debería depender de una heurística.

A 375 px el documento no desborda (`docW=375 / viewport=375`): la tabla y el
código scrollean por dentro, como estaba previsto.
